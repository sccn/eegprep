EEGPrep Phase 3 Statistics Package Notes

Design Decisions

  • Placed the package at src/eegprep/functions/statistics to mirror EEGLAB's functions/statistics folder.
  • Centralized formulas in _core.py and added same-name modules for EEGLAB discoverability without duplicating numerical code.
  • Made NumPy's final axis the public case/subject/surrogate axis by default. Functions accept an explicit axis argument when callers need another case axis.
  • statcond returns a StatcondResult with named fields and can still be unpacked as (stat, df, pvalue, surrogate).
  • Two-way ANOVA helpers return named row, column, and interaction effects to avoid inheriting EEGLAB's inconsistent output ordering between anova2_cell and anova2rm_cell.

Deviations

  • MATLAB row-vector/column-vector heuristics are not emulated. EEGPrep treats the selected axis as the case axis explicitly, which is clearer for NumPy callers.
  • statcondfieldtrip remains out of scope because it depends on FieldTrip-style external statistics machinery.
  • teststat is a deterministic Python smoke helper instead of a verbose MATLAB command-window demo.
  • Surrogate resampling is seeded through NumPy generators and returns explicit surrogate grids rather than MATLAB's arraycomp/precomp cell-array optimization surface.

Tradeoffs

  • Unpaired one-way ANOVA supports unequal case counts for usefulness, while balanced two-way ANOVA requires matching cell shapes to preserve the EEGLAB formula contract.
  • Runtime code does not call or import the vendored EEGLAB tree. MATLAB parity tests add the vendored statistics folder to MATLAB Engine only inside the test fixture.

Open Questions

  • Future STUDY work may want root-level eegprep.statcond exports; this phase keeps the public path under eegprep.functions.statistics to avoid broad root API churn.
  • Cluster-based correction from EEGLAB statcond is not implemented; no Phase 3 consumer required it.
