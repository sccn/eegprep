EEGPrep Phase 6 STUDY And Group-Level Notes

Phase 6 deepens standalone STUDY workflows without adding runtime dependencies on the vendored EEGLAB tree or pretending external LIMO behavior is available.

Phase 6 Design Decisions

  • Added EEGLAB-named STUDY design helpers for factor listing, imported group variables, design matrix construction, design rebuilds, independent-variable snapshots, and one/two-level variable metadata.
  • Kept existing STUDY GUI dialogs unchanged. The new work is backend/API and console-visible, so GUI visual parity artifacts and GUI Agent QA were not applicable for this branch.
  • Extended cached measure readers for ERP, spectrum, ERSP, ITC, topographies, and PAC cache detection. PAC reads only succeed when an EEGPrep-owned pacdata cache exists.
  • Added deterministic clustering helpers that run in package: robust k-means, silhouette-based k selection, affinity-propagation-style exemplar clustering, centroid calculation, and outlier detection.
  • Added standalone consistency helpers for dataset/session checks, uniform channel distribution checks, and cached measure-shape reports.
  • Implemented LIMO entry points as explicit NotImplementedError limitations because EEGPrep does not ship an external LIMO toolbox equivalent.

Phase 6 Deviations

  • EEGLAB sidecar file semantics are represented through EEGPrep-owned JSON/MAT sidecar writing and in-memory STUDY caches. Runtime code does not read from EEGLAB's reference checkout.
  • std_addvarlevel stores EEGLAB-like level values of one or two; the previous numeric level list is preserved as levelindex for deterministic downstream use.
  • std_apcluster is a deterministic standalone affinity-propagation implementation for EEGPrep workflows, not a dependency on EEGLAB's MATLAB apcluster helper.

Phase 6 Tradeoffs

  • Subject filtering is applied only when the leading cache axis is the loaded dataset axis. Child-cluster component rows are not silently treated as subjects.
  • The LIMO surface is exported so users receive clear limitations from familiar names, but the parity matrix keeps those rows classified as external dependency limitations rather than implemented analysis behavior.
  • GUI dialogs were not broadened in this phase to avoid conflicting with the parallel Phase 5 user-facing option work.

Phase 6 Open Questions

  • A future phase can add native PAC precompute once there is a tested EEGPrep PAC implementation to populate pacdata.
  • If standalone LIMO-equivalent modeling becomes a product goal, it should be scoped as a separate statistics feature rather than hidden inside these limitation functions.

Design Decisions

  • Implemented the useful channel-location core as standalone Python modules under src/eegprep/functions/sigprocfunc: readlocs, writelocs, convertlocs, chancenter, floatread, floatwrite, snapread, and EGI location lookup.
  • Added EEGLAB-style public wrappers under src/eegprep/functions/popfunc for pop_readlocs, pop_writelocs, pop_chancenter, pop_chancoresp, pop_loadbci, and pop_snapread.
  • Kept runtime behavior independent of the vendored EEGLAB tree. Packaged montage files are read explicitly through package resources or user-supplied paths.
  • Reused the new channel-location parser/writer inside pop_chanedit so GUI and command workflows share one implementation.
  • Preserved EEGLAB-facing 1-based channel indices in readchans, elecind, omitchans, and channel-correspondence return values.

Deviations

  • No new channel-location GUI dialogs were added in this phase. The command paths are tested and history-capable; GUI visual parity artifacts were therefore not applicable.
  • pop_chancoresp implements the workflow-supporting label and fiducial pairing behavior without recreating EEGLAB's full interactive listbox editor.
  • BCI2000 and SnapMaster support is limited to documented, fixture-testable import surfaces. Obsolete or toolbox-dependent readers are classified in the matrix instead of being ported blindly.
  • Coordinate conversion keeps original Cartesian coordinates stable during cart2all and fills derived fields without avoidable spherical round-trip drift.

Tradeoffs

  • Text location parsing accepts common EEGLAB formats and explicit custom column formats, but it rejects malformed rows early instead of silently padding incompatible files.
  • EGI sensor-location lookup maps 128/129 and 256/257-channel workflows to packaged HydroCel montage resources. Legacy binary EGI RAW import remains consolidated under modern file import routes.
  • Low-level floatread and floatwrite are implemented for EEGLAB-style binary helper coverage, while high-level EEG file export remains owned by existing pop_writeeeg paths.

Open Questions

  • Future GUI parity work may add EEGLAB-style modal dialogs for pop_readlocs, pop_writelocs, pop_chancenter, and pop_chancoresp; this phase intentionally shipped API and console behavior first.
  • Rare historical readers such as Neurodata, old EGI segmented RAW, and BIOSIG conversion shims should stay skipped or consolidated until a documented user workflow and deterministic fixture justify them.
