Phase 1 Core Parity Matrix Notes

Design Decisions

  • Created the machine-readable matrix at docs/parity/eeglab_core_parity_matrix.json so it is committed documentation/tooling data, not package runtime data.
  • Defined in-scope EEGLAB public/semi-public functions as top-level .m files under functions/adminfunc, guifunc, miscfunc, popfunc, sigprocfunc, statistics, studyfunc, and timefreqfunc.
  • Added one explicit plugin row for plugins/clean_rawdata/clean_asr.m because the audit names its unsupported Riemannian ASR mode.
  • Kept src/eegprep/eeglab reads inside validator/test tooling only; no installed package runtime path depends on the vendored EEGLAB tree.
  • Classified likely user aliases as port even when an existing EEGPrep function can be the implementation delegate.

Tradeoffs

  • The matrix intentionally contains many port rows instead of aggressive stale_skip rows; later phases should reclassify only from concrete workflow evidence.
  • MATLAB path, deployment, help-generation, GUI shim, and compatibility helpers use matlab_runtime_skip rather than being ported into standalone Python runtime code.
  • External LIMO, FieldTrip, Brainstorm, and legacy BIOSIG-specific bridges use external_dependency_skip unless a later phase supplies a real standalone dependency path.
  • Existing STUDY and option-limited functions with visible coming-soon or NotImplemented paths are partial so later phases do not treat them as complete.

Deviations

  • The validator does not scan EEGLAB @class folders, supportfiles, or whole plugin ecosystems because the parent epic and Phase 1 issue scope only the first seven core audit categories.
  • No feature behavior was ported in this phase; this PR only adds the matrix, validation tooling/tests, and documentation contracts.

Open Questions

  • Phase 2 should decide whether legacy BIOSIG wrappers should remain external_dependency_skip or become thin delegates to modern EEGPrep import paths.
  • Phase 5 should decide whether pop_runscript MATLAB/text script rejection is a permanent standalone limitation or needs a compatibility-facing wrapper behavior.
