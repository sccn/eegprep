EEGPrep Phase 7 Long-Tail Core Helpers Notes

Phase 7 closes the remaining audit-approved helper and wrapper gaps that were still actionable after Phases 2-6, while classifying obsolete or toolbox-dependent MATLAB surfaces explicitly in the parity matrix.

Phase 7 Design Decisions

  • Added standalone EEGLAB-named ICA projection helpers for component activations, back-projection, component variance, and percent variance accounted for. The implementation reuses EEGPrep's existing finite matrix multiplication and rejection activation helpers instead of adding parallel ICA math.
  • Added rejection/statistical compatibility helpers for probability, entropy, thresholding, kurtosis, joint probability, and trend rejection surfaces needed by current menus, tests, and likely user-typed workflows.
  • Added legacy user-facing wrappers for pop_averef, pop_compareerps, pop_findmatchingcomps, pop_fusechanrej, pop_icathresh, pop_rejchanspec, and pop_topochansel. Each wrapper either delegates to an existing modern EEGPrep path or implements the thin compatibility behavior directly with replayable command history.
  • Added packaged help Markdown for every new user-facing pop_* wrapper. No runtime code reads from the vendored EEGLAB checkout.
  • Updated public exports only for user-facing wrappers and helpers that EEGLAB users are likely to import or type directly.

Phase 7 Deviations

  • MATLAB-only GUI shims, figure utilities, demos, install/deployment helpers, and old command-window support functions remain skipped instead of being recreated as stale runtime code.
  • Legacy external ICA backends such as JADE, SOBI, and binary ICA routes remain external-dependency skips unless a modern EEGPrep backend is deliberately added.
  • No new EEGLAB-style GUI dialogs were added. pop_topochansel reuses the existing EEGPrep channel selector for GUI fallback, so visual parity captures were not applicable.

Phase 7 Follow-Ups

  • #146 tracks time-warped newtimef marker and cycle GUI workflows.
  • #147 tracks exact correct_mc random-symbol distribution fitting.
  • #148 tracks phase-amplitude coupling time-frequency helpers.
  • #149 tracks remaining STUDY plotting, precompute, and selection long-tail helpers.

Phase 7 Verification Notes

  • Focused tests cover wrapper delegation/history, console auto-store behavior for pop_averef, spectral channel rejection, topographic channel selection, ICA helper math, and rejection helper outputs.
  • The parity matrix now has no port or partial rows without either an implementation/classification or a concrete follow-up issue.

EEGPrep Phase 5 Unsupported User-Facing Options Notes

Phase 5 closes option-level gaps in existing user-facing functions while keeping EEGPrep standalone and explicit about MATLAB-only or toolbox-dependent behavior.

Phase 5 Design Decisions

  • Implemented concrete standalone option paths for pop_export expressions, filename-backed pop_epoch data, pop_editset file assignments, pop_comperp display/significance toggles, pop_erpimage event sorting, and headplot_setup preview/original-location options.
  • Kept MATLAB workspace expression evaluation out of runtime code. Users must pass Python values directly or provide concrete file paths so GUI and console history remain replayable.
  • Classified legacy or external-toolbox behavior as explicit non-goals where a standalone path is not maintainable: legacy pop_eegfilt FFT filtering, MATLAB/text pop_runscript, unsupported pop_runica algorithms, FieldTrip-style coregister methods, and full Riemannian ASR processing.
  • Did not change GUI layout or dialog geometry. Existing GUI controls now reach more supported paths, so new visual parity captures were not required for this phase.

Phase 5 Tradeoffs

  • pop_export accepts a restricted numeric expression language instead of arbitrary Python evaluation. This covers common scale/log/clip transforms without exposing broad runtime objects through command history.
  • clean_artifacts(Distance='Riemannian') uses the supported calibration-time Riemannian ASR estimate. Full Riemannian ASR processing remains unported and raises a clear error when requested directly.
  • pop_envtopo remains a one-dataset wrapper because multi-dataset component envelopes need a deliberate group workflow rather than a silent merge of dataset-specific ICA maps.
  • Post-review tightening keeps useful options permissive but explicit: selected safe pop_export keywords are accepted, missing pop_editset paths fail as missing files, dataformat applies to numeric ICA imports, pop_comperp standard-deviation traces use EEGLAB's dataset-axis spread, and unknown ASR distance names are rejected.

Phase 5 Verification Notes

  • Focused tests cover sample-data export, filename-backed epoching, editset history replay, invalid option paths, plot option behavior, clean ASR limitations, and legacy non-goals.
  • MATLAB parity tests remain available behind the existing skip behavior. Local MATLAB parity execution exposed unrelated EEGLAB save-wrapper failures, so Python-focused runs use EEGPREP_SKIP_MATLAB=1 where needed.

EEGPrep Phase 6 STUDY And Group-Level Notes

Phase 6 deepens standalone STUDY workflows without adding runtime dependencies on the vendored EEGLAB tree or pretending external LIMO behavior is available.

Phase 6 Design Decisions

  • Added EEGLAB-named STUDY design helpers for factor listing, imported group variables, design matrix construction, design rebuilds, independent-variable snapshots, and one/two-level variable metadata.
  • Kept existing STUDY GUI dialogs unchanged. The new work is backend/API and console-visible, so GUI visual parity artifacts and GUI Agent QA were not applicable for this branch.
  • Extended cached measure readers for ERP, spectrum, ERSP, ITC, topographies, and PAC cache detection. PAC reads only succeed when an EEGPrep-owned pacdata cache exists.
  • Added deterministic clustering helpers that run in package: robust k-means, silhouette-based k selection, affinity-propagation-style exemplar clustering, centroid calculation, and outlier detection.
  • Added standalone consistency helpers for dataset/session checks, uniform channel distribution checks, and cached measure-shape reports.
  • Implemented LIMO entry points as explicit NotImplementedError limitations because EEGPrep does not ship an external LIMO toolbox equivalent.

Phase 6 Deviations

  • EEGLAB sidecar file semantics are represented through EEGPrep-owned JSON/MAT sidecar writing and in-memory STUDY caches. Runtime code does not read from EEGLAB's reference checkout.
  • std_addvarlevel stores EEGLAB-like level values of one or two; the previous numeric level list is preserved as levelindex for deterministic downstream use.
  • std_apcluster is a deterministic standalone affinity-propagation implementation for EEGPrep workflows, not a dependency on EEGLAB's MATLAB apcluster helper.

Phase 6 Tradeoffs

  • Subject filtering is applied only when the leading cache axis is the loaded dataset axis. Child-cluster component rows are not silently treated as subjects.
  • The LIMO surface is exported so users receive clear limitations from familiar names, but the parity matrix keeps those rows classified as external dependency limitations rather than implemented analysis behavior.
  • GUI dialogs were not broadened in this phase to avoid conflicting with the parallel Phase 5 user-facing option work.

Phase 6 Open Questions

  • A future phase can add native PAC precompute once there is a tested EEGPrep PAC implementation to populate pacdata.
  • If standalone LIMO-equivalent modeling becomes a product goal, it should be scoped as a separate statistics feature rather than hidden inside these limitation functions.

EEGPrep Phase 2 File Format And Channel-Location Notes

Design Decisions

  • Implemented the useful channel-location core as standalone Python modules under src/eegprep/functions/sigprocfunc: readlocs, writelocs, convertlocs, chancenter, floatread, floatwrite, snapread, and EGI location lookup.
  • Added EEGLAB-style public wrappers under src/eegprep/functions/popfunc for pop_readlocs, pop_writelocs, pop_chancenter, pop_chancoresp, pop_loadbci, and pop_snapread.
  • Kept runtime behavior independent of the vendored EEGLAB tree. Packaged montage files are read explicitly through package resources or user-supplied paths.
  • Reused the new channel-location parser/writer inside pop_chanedit so GUI and command workflows share one implementation.
  • Preserved EEGLAB-facing 1-based channel indices in readchans, elecind, omitchans, and channel-correspondence return values.

Deviations

  • No new channel-location GUI dialogs were added in this phase. The command paths are tested and history-capable; GUI visual parity artifacts were therefore not applicable.
  • pop_chancoresp implements the workflow-supporting label and fiducial pairing behavior without recreating EEGLAB's full interactive listbox editor.
  • BCI2000 and SnapMaster support is limited to documented, fixture-testable import surfaces. Obsolete or toolbox-dependent readers are classified in the matrix instead of being ported blindly.
  • Coordinate conversion keeps original Cartesian coordinates stable during cart2all and fills derived fields without avoidable spherical round-trip drift.

Tradeoffs

  • Text location parsing accepts common EEGLAB formats and explicit custom column formats, but it rejects malformed rows early instead of silently padding incompatible files.
  • EGI sensor-location lookup maps 128/129 and 256/257-channel workflows to packaged HydroCel montage resources. Legacy binary EGI RAW import remains consolidated under modern file import routes.
  • Low-level floatread and floatwrite are implemented for EEGLAB-style binary helper coverage, while high-level EEG file export remains owned by existing pop_writeeeg paths.

Open Questions

  • Future GUI parity work may add EEGLAB-style modal dialogs for pop_readlocs, pop_writelocs, pop_chancenter, and pop_chancoresp; this phase intentionally shipped API and console behavior first.
  • Rare historical readers such as Neurodata, old EGI segmented RAW, and BIOSIG conversion shims should stay skipped or consolidated until a documented user workflow and deterministic fixture justify them.
